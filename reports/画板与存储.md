# 画板与本地存储

## 先按写入器识别文件

错题本的 SimpleBoard、Sketch 历史画板和 Blackboard 多页画板各有独立的原生读写入口。新测评还有三种以 .bin 结尾的 JSON 文件。只有文件名、没有目录和消息结构时，header.bin 的类型无法唯一确定。

|---|---|---|

| Sketch actions.bin | 顶层字段 1 为 BoardHead，字段 2 为 BoardBody。第 1 版在 body 中重复存储 Any。后续版本用 ActionContent 包装 Any，并可附加 graphSnapshot 和 resetData。触摸记录带时间、动作、指针属性和坐标。 | EzyDrawBoard、VersionParseFactory、GraphTaskParseVersion1 至 5。云笔记 BoardDataFactory.buildHead 写入版本 5。 |

## 五个应用之间的差异

中育云笔记、优课畅学、新测评、错题本、随身答都附有 Sketch、Blackboard 和 SimpleBoard 的协议文本。五份画板定义统一 BOM 和换行后相同。错题本保留了 SimpleBoard 的完整 Java 类名和实际存取方法，新测评也保留 SimpleBoard 生成类与读取 BIN 的视图方法。其他三个 APK 的同名 schema 本身不能证明用户操作会写出同一种简笔 BIN。优课畅学另有 RoleType、ServerBean、UpdateSetting、UserBean 四份定义。其余六个 APK 未发现这组应用画板 schema。

错题本与新测评的原生 SimpleBoard 解析器都能从网页导出物读回两条路径。错题本、优课畅学、新测评及随身答的 Sketch 解析器均读回 6 条动作、其中 2 条为触摸记录。中育云笔记在隔离 ART 中调用本包 Sketch 解析器时缺少 makeExtensionsImmutable 方法；原 DEX 中 DrawBoard 调用了该方法，同包的 Protobuf 运行时继承链缺少对应实现。云笔记实际旧课堂笔记的完整业务流程仍待复核。[逐包读回记录](evidence/art/variants.json)

错题本原生 SimpleBoardView 已走通「载入网页的两笔 → Android 触摸增加一笔 → 原生保存三笔 → 网页再加一笔 → 原 APK 读回四笔」。另在 320 × 240 原生视图设置 640 × 480 背景，用原路径 saveData 生成 WebP 与 BIN。简笔 BIN 没有画布宽度，Web 导入会保留背景比例，默认用图片宽度；已知原生视图宽度时，可在尺形按钮输入像素宽度。测试输入 320 后，导出文件保留原背景字节、成员名与四笔，原生读回通过。[原生仪器测试](evidence/art/page-read.txt) · [带底图原生样本](evidence/board/native-simple-page.zip) · [有底图的浏览器截图](evidence/board/native-background-web.png) · [原生读回](evidence/art/native-background-read.txt) · [WebP 容器规范](https://developers.google.com/speed/webp/docs/riff_container)

Blackboard 网页支持层叠文字、填充或描边图形、图像与笔迹。文字和几何资源从快照或同页分片取值，图片路径按原生 SourceRouterRecord 定位到同一画板根目录的 res/image。已验证本地构造的文字、椭圆、多边形和 PNG 示例可以同时预览、加笔并保留原文件。该页式格式的多指历史和演示文稿仍需业务样本验证。[有图文的页面样本](evidence/board/schema-artwork.zip) · [浏览器实测截图](evidence/board/artwork.png)

五款原 APK 在 Android ART 上分别用自带的 Protobuf 类读取并重写同一份网页图文页中的 Header、PageRouter、RouterRecord、PageSnapshot、TouchSource、CommandSource、TextSource、GeometrySource、FileSource。45 组结果的解码字段均相等。每款应用有七类写回字节完全相同，快照和触摸分片的字节编码有差异，解析值一致。比较编码时应使用原文件的摘要，重新编码后需重算路由中的摘要。云笔记的 NewPaintFragment 复制流程也分别引用了 page_router.bin、snapshot.bin 和 *_command.bin。[逐消息结果](evidence/art/page-variants.json) · [核对程序](../tools/verification/verify_board_variants.py)

### SimpleBoard 整笔擦除

错题本和新测评在建立每笔路径时保存命中矩形。沿宽、高分别判断，如果一边短于当时橡皮的直径，就在该轴两端各加一个半径。触点须先落入这个矩形，左、上边界包含在内，右、下边界排除。原版接着检查触点到相邻原始采样点所连线段的距离。虚线的空隙也能命中，单采样点没有可检查的线段，两个重合采样点则有一条长度为零的线段。一处触点可删掉多条重叠笔迹。[错题本构造边界](evidence/board/simple-eraser/rea-bounds.json) · [错题本擦除方法](evidence/board/simple-eraser/rea-hit.json) · [新测评擦除方法](evidence/board/simple-eraser/rea-assessment-hit.json)

默认半径为 40。缩放后，原版通过当前相机矩阵把半径换回页面坐标。已建路径的命中矩形保留创建时的值。原版按 Android 单精度浮点数计算距离，因此恰好在半径上的两个触点也可能得到不同结果。在横线 (20,48) 到 (260,48) 上，触点 (160,8) 会擦掉它，(130,8) 会留下它。网页按原版顺序计算这几个中间值。[两款原画板各 17 组结果](evidence/board/simple-eraser/native.json) · [Flutter 命中计算](../board_editor/lib/simple_erase.dart)

验证从原 APK 自带的 schema 生成一份七笔样本，在 Android 11 上向两个原版 View 发送按下、移动和抬起事件，并调用各自的保存方法。浏览器打开同一文件，按下时由七笔变六笔，拖动后剩四笔。网页导出的 164 字节与两个原版各自擦除后的文件逐字节相同。两个原版重开网页文件后，绘制的 320 × 240 位图均与各自直接擦除的结果逐像素相同。网页撤销和空擦均保留原始 298 字节，重做恢复这 164 字节。网页与原生采用不同的栅格绘制器，按亮度低于 180 计，网页 1,413 个墨迹像素与原生 1,433 个墨迹像素中有 1,408 个位置重合。[原始 BIN](evidence/board/simple-eraser/input.bin) · [网页导出的 BIN](evidence/board/simple-eraser/web.bin) · [按住橡皮时的网页](evidence/board/simple-eraser/held.png) · [网页重开截图](evidence/board/simple-eraser/editor.png) · [像素与回读核对](evidence/board/simple-eraser/comparison.json)

复测时，在隔离模拟器上运行原版 View 验证脚本，从 Chromium 验证入口选择 `--simple-eraser`，再给原版脚本传 `--read` 和网页导出的 BIN。对照脚本同时检查路径、文件字节、两端的位图和抬手前后的光标。浏览器也用触摸事件验证了系统取消时保留已经擦掉的笔迹，撤销可恢复原稿。[原版 View 验证脚本](../tools/verification/verify_simple_eraser.py) · [浏览器操作](../tools/verification/check-simple-eraser.cjs) · [对照脚本](../tools/verification/compare_simple_eraser.py)

## 错题本的笔记目录、ZIP 和清单

错题本有 ZIP 和文件清单两条读取路径。原包的本地打包方法从笔记目录的直接子项开始递归，因此 ZIP 根下直接出现 `header.bin`、`p1/` 和 `res/`。测试包保留了原目录的空子目录项。另一条路径使用 `fileList.json`，内容是带 `url` 和 `md5` 的对象数组。错题本为每项计算大写十六进制 MD5，页面 `router.bin` 内各分片采用另一套 SHA-256 校验。[原生打包代码](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/sources/%E9%94%99%E9%A2%98%E6%9C%AC/java/com/zykj/mistake/service/UploadIntentService.java) · [原生清单模型](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/sources/%E9%94%99%E9%A2%98%E6%9C%AC/java/com/zykj/mistake/utils/NoteRemoteFileInfo.java) · [原生测试包](evidence/board/native-note-bundle.zip)

在 Android 11 上调用错题本的原始目录遍历方法，以本地文件提供数据，得到含 17 条资源的清单。首次通过原生清单读取器恢复时，传输回调执行 18 次，包含清单本身。读取完成后原应用删除临时清单，其余 17 个文件与输入逐字节一致。第二次打开同一笔记，仅重新读取清单、`screenshot.png` 和 `res/image/tiles.png`。改动本地 `p1/snapshot.bin` 后，原生读取器又单独恢复了该文件。这些检查使用合成 URL 及本地回调。[清单及逐文件 MD5](evidence/board/native-note-bundle.json) · [原生回读结果](evidence/art/note-bundle-restore.txt)

网页的「打开画板文件夹」可以载入解包后的笔记，也能识别同一目录树中有 WebP 底图的 SimpleBoard 草稿、Sketch 和 Blackboard 页面。文件夹导出为 ZIP，保留浏览器返回的文件与相对路径。浏览器文件选择器只返回文件，原 ZIP 中的空目录可通过直接打开 ZIP 保留。在 Chromium 内打开本次原生笔记包后，未编辑的 ZIP 与原包逐字节相同。用文件夹入口打开并导出时，18 个普通文件内容均保持一致。[浏览器验证](evidence/board/note-folder-browser.txt) · [文件夹导出的 ZIP](evidence/board/folder-note.zip)

网页追加笔迹会更新页面快照及路由，新增命令分片、触摸分片和页内预览图。原下载清单仍描述来源文件的 URL 和摘要。对比清单可见 15 个匹配项、2 个内容已变的项目和 3 个新增文件。错题本通过 ZIP 入口打开网页导出物，只读取一次 ZIP，展开的 21 个文件均与浏览器归档里的原始字节相同。错题本再从恢复的快照和触摸分片构建原生图元，两笔分别绘出了 128 和 743 个非透明像素。命令 `python3 tools/read-data.py --type note-bundle 文件.zip` 可以离线区分已改变、缺少及新增的文件。存在多个可能的清单目录时，可用 `--note-base` 指定已知的源 URL 目录。[编辑后的笔记](evidence/board/folder-note-edited.zip) · [编辑前后清单对照](evidence/board/note-folders.json)

## 云笔记的页序和资源清单

旧版云笔记将页面所在的 Android 绝对目录按翻页顺序写入 `index.json`。`res.json` 另存资源对象数组，每项的 `local` 是设备上的文件名，`service` 是服务端地址。当笔记没有有效的 Room 资源记录时，旧编辑器逐项读取页序，跳过已不存在的目录，保留重复引用。它把目录交给画板，并从目录中的 `thumbnail.jpg` 取侧栏预览。[REA 读取原 APK 的页序方法](evidence/board/cloud-index/rea-read-index.json) · [原编辑器创建页面与预览](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/sources/%E4%B8%AD%E8%82%B2%E4%BA%91%E7%AC%94%E8%AE%B0/java/com/friday/paint/view/ThePaintFragment.java#L1333)

Flutter 网页打开 ZIP 或整个笔记文件夹时，会将原设备目录对应到包内的 `actions.bin`。来源前缀有多个同等匹配时，先用资源清单中的本地路径核对，仍有歧义时会提示。测试样本列了「第2页、missing、第一页、第2页」，另有一个未列入清单的目录。Chromium 和原版云笔记旧编辑器都得到「第2页、第一页、第2页」。在第三个翻页位置续写后，三个位置的笔数由 2、1、2 变为 3、1、3。五个归档成员中只有 `第2页/actions.bin` 变化。原版云笔记解包并读回了页序，笔数由错题本原版 Sketch 播放器回读。云笔记自己的旧播放器在解析文件头时遇到包内缺失的 `makeExtensionsImmutable`。[含原包生成清单的测试 ZIP](evidence/board/cloud-index/native.zip) · [网页加笔后的 ZIP](evidence/board/cloud-index/web.zip) · [原生回读、摘要与解码结果](evidence/board/cloud-index/comparison.json)

有资源记录时，Room 按笔记 ID 和用户 ID 查询 `ResourceEntity`，过滤 `wasDeleted`。新版 `NotePageOrder` 还检查页目录的 `.page_deleted` 标记。每页优先选 `page_mdb/data.mdb`，其次是 `page_mdb/lock.mdb`、`screenshot.png`、`snapshot.bin`，最后是其他文件。同一优先级取路径字典序最小的记录，然后按所选记录的 `pageIndex` 和页面目录名排列。旧编辑器的数据库分支则按页名保留首次出现的记录，再按该记录的 `pageIndex` 排序。[REA 对原包优先级方法的解码](evidence/board/cloud-index/rea-page-priority.json) · [完整的页面选择代码](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/sources/%E4%B8%AD%E8%82%B2%E4%BA%91%E7%AC%94%E8%AE%B0/java/com/friday/common/helper/NotePageOrder.java#L90)

在 Android 11 上用云笔记原包写入 8 条合成记录，关闭后重新打开数据库，原查询返回 7 条有效资源。另为一个页目录创建删除标记，新版列表显示 2 页，旧编辑器仍显示 3 页。清除标记后新版也显示 3 页。旧编辑器使用的页索引为 0、2、4，新版选出的代表记录为 0、2、2。解码输出中的 `legacy_editor_pages` 和 `pages` 可直接对照两种顺序；旧编辑器的查询没有指定 SQL 排序，同一页以本次游标最先返回的资源为准。[原包写入的 SQLite 数据库](evidence/board/cloud-index/page-order.db) · [导出和读回验证程序](../tools/verification/verify_cloud_index.py)

云笔记旧侧栏直接加载页目录中的 `thumbnail.jpg`。网页编辑普通 Sketch 笔记后会同时更新笔迹和预览。旧文件头版本低于 2 或头内 `createDate` 小于 1546272000 时，原应用还会把这张 JPEG 作为图片加入画板。[原包旧版本分支](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/sources/%E4%B8%AD%E8%82%B2%E4%BA%91%E7%AC%94%E8%AE%B0/java/com/zykj/sketch/core/record/RecordControl.java#L489) · [普通静态页的原包读回](#sketch-静态笔记与-jpeg-预览)

## Blackboard V6 的文字和几何编辑

打开完整页面 ZIP 后，工具栏的「编辑图元」按名称列出文字、椭圆和多边形。文字可改内容、字号、颜色及文本框尺寸。椭圆可改宽高、描边宽度及填充方式。多边形可以逐行修改顶点。水平移动和垂直移动以原页面像素计，允许负值。网页保留原资源分片，将改动写入新命令和当前快照。普通导出保留整个包，云笔记副本可触发新版原生导入器。[原始测试页](evidence/board/artwork-edit-base.zip) · [网页编辑后](evidence/board/web-artwork-edited.zip) · [云笔记副本](evidence/board/web-artwork-edited-cloud.zip)

| 从原始页逐条执行的操作 | 错题本原 APK 读回 |
|---|---|
| 改文字并移动 | 内容 `Board 42`，字号 36，ARGB `FF164E91`，原点从 (40, 35) 移至 (72, 47) |
| 调整椭圆 | 宽 168、高 82、描边 7、ARGB `FF794523` |

### V5 画板变换与触摸坐标

原生播放器把平移和缩放应用在根图元的 Android Matrix 上。ActionTranslation 的 keep 为真时追加位移，否则只替换消息中指定轴的平移分量。ActionZoom 的 keep 为真时围绕记录的中心追加缩放，否则先保留旧平移，再应用新缩放。V5 调度器未为 ActionResetMatrix 生成回放任务。每笔开始时，原应用把屏幕触点映回图元局部坐标，显示时重新映射笔迹位置。笔宽按屏幕画布单位绘制。网页「画板变换」可将移动或缩放写回 BIN；工具栏「平移与缩放」用于浏览。

ACTION_WRITING_MOVE 模式在第二根手指落下时撤掉当前临时笔迹。之后按两根手指的中点相对首次双指接触的位移平移画板。ACTION_WRITING_MOVE_VERTICAL 使用中点的纵向差。手势结束后的单指抬起不会产生额外笔迹。原生手写图元在 DOWN 和 MOVE 时采点，UP 用来结束笔迹。网页写入新笔时把末端位置记录为最后一个 MOVE。

### Sketch 的图片、叠放顺序与版本差异

Sketch 的图片文件在 `actions.bin` 旁的 `res/<path>`。path 可以包含子目录。原生 ImageGraph 从字节解码位图，并用动作中的 width 除以位图宽度，得到等比缩放系数。width 和 height 同时参与定位。positionFlag 的 1、2、3 表示左上、上中、右上，4 和 6 表示左中、右中，7、8、9 表示左下、下中、右下；0 及这里未单独处理的标志居中。原生 onMeasure 对当前世界矩阵先求逆，再追加缩放和对齐平移，因此已有画板变换时，图片边缘可能超出画布。[原类及注释](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/sources/%E9%94%99%E9%A2%98%E6%9C%AC/java/com/zykj/sketch/core/graph/ImageGraph.java) · [带 PNG 和子目录 JPEG 的样本](evidence/board/sketch-images.zip)

NormalViewModel 从 APK 资产读取模型字节，选择题识别入口把模型、位图、角点、试卷配置 JSON、页号及结果数组交给 AnswerSheetNative。独立在主机用 LiteRT 的普通 CPU 核和参考核分别推理，全零、全一和对角线输入得到的三对分数在两种实现之间逐项相同。输出下标与实际涂卡含义的对应关系还缺经标注的答题卡样本。[原应用调用](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/sources/%E6%96%B0%E6%B5%8B%E8%AF%84/java/com/zykj/evaluation/p057ui/sheet/normal/NormalViewModel%24identifyAnswers%242.java#L87) · [可复现推理](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/tools/verification/verify_answer_model.py) · [输出数值](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/reports/evidence/answer-sheet/inference.json)

安装 Python 包 ai-edge-litert 后，`python3 tools/read-data.py android/新测评/assets/sel_judge_06.tflite` 可直接读取该模型。结构检查只解析 FlatBuffer，独立推理使用上面的验证脚本。

### 云笔记的图片分类模型

中育云笔记的 `assets/nsfw.tflite` 为 23,591,976 字节的 TFL3 FlatBuffer，格式版本为 3。单个子图有 216 个张量、90 个算子，其中卷积 53 个。输入为 1 × 224 × 224 × 3 的 float32 张量，输出为两个 float32 分数。原客户端将图片缩放到 256 × 256，再取中心 224 × 224 并按 B、G、R 三通道准备输入。文件摘要和全部权重缓冲区摘要可独立复核。本项核对了模型布局与调用方维度，实际图片分类准确率没有参与测试。[模型文件](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/android/%E4%B8%AD%E8%82%B2%E4%BA%91%E7%AC%94%E8%AE%B0/assets/nsfw.tflite) · [张量、算子和权重摘要](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/reports/evidence/cloud-image-model.json) · [原调用及注释](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/sources/%E4%B8%AD%E8%82%B2%E4%BA%91%E7%AC%94%E8%AE%B0/java/p141f2/C9167d.java#L81)

### Android 的启动性能配置

7 个 APK 在 `assets/dexopt/` 内附有两种二进制文件。主文件 `baseline.prof` 的文件头为 `pro\0`、版本 010，元数据 `baseline.profm` 的文件头为 `prm\0`、版本 002。两种文件都使用小端整数和 zlib。主文件为每个 DEX 保存校验值、热点方法、类 ID 增量序列、启动期与启动后方法位图。元数据记录 DEX 名称、类型表大小和类定义序号。工具可以分别解码两类文件。对应同一类的类型 ID 和类定义序号可能不同。[解码器](../tools/art_profile.py) · [AndroidX 格式实现](https://github.com/androidx/androidx/blob/androidx-main/profileinstaller/profileinstaller/src/main/java/androidx/profileinstaller/ProfileTranscoder.java)

原包的性能配置引用原 DEX 的 ZIP CRC32。重编 APK 保留了原始资产，但 smali 重装配后 DEX 的 CRC32 已改变。随重编 APK 提供的 Android 11 `.dm` 按新 DEX 生成，逐项核对类型、方法签名、参数和类定义。在网阅联考的两个 DEX 中，类型与方法索引保持一致，类定义的排列有变化，伴随元数据已按实际顺序重算。[性能配置生成器](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/tools/build_profile_metadata.py) · [原包与重编包逐 DEX 核对](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/reports/evidence/art-profiles.json) · [Android 官方安装与验证说明](https://developer.android.com/topic/performance/baselineprofiles/manually-create-measure)

### OkHttp 附带的公共后缀表

10 个 APK 附带域名公共后缀规则。优课畅学和中育管控桌面直接从 assets 读取 `PublicSuffixDatabase.list`，另 8 个使用 gzip 压缩的 `publicsuffixes.gz`。解压后的结构相同。先读 4 字节大端整数，再按该字节数读取以换行分隔的 UTF-8 普通规则，随后以相同方式读取例外规则。普通段包含 `com` 和以 `*.` 开头的通配规则，例外段直接存储域名。四个版本的普通规则数分别为 8,664、8,845、9,499 和 9,764，各含 8 条例外。逐包用拆出的文本重建两段及其长度，结果与原资产解压后的字节完全一致。选课包未含这两种资源。[逐包文件与摘要](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/reports/evidence/public-suffix.json) · [错题本的压缩读取器](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/sources/%E9%94%99%E9%A2%98%E6%9C%AC/java/okhttp3/internal/publicsuffix/PublicSuffixDatabase.java#L210) · [优课畅学的资产读取器](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/sources/%E4%BC%98%E8%AF%BE%E7%95%85%E5%AD%A6/java/p291w9/C10475a.java)

### 图片与 HTTP 磁盘缓存

九个 APK 的字节码含有 `libcore.io.DiskLruCache` 日志头。选课和问卷调查中没有找到该常量。日志的前四行依次为格式标记、日志版本、应用缓存版本、每条记录的数据文件数，第五行为空行。随后每行记录一次操作。DIRTY 开始写入，CLEAN 提交并列出各文件的十进制字节数，READ 记录读取，REMOVE 移除条目。槽文件名为 `键.0`、`键.1` 等。解码器会列出尚未提交的键，并将提交长度与同目录文件大小核对。[逐 APK 的字节码位置](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/reports/evidence/disk-cache/apk-classes.json) · [命令行解码器](../tools/disk_cache.py)

| 原包及缓存组件 | 应用缓存版本 | 文件布局与实测 |
|---|---:|---|
| 领创平板管理，Glide | 1 | 每个键只有一个数据文件。原包提交后读回 37 字节测试数据，另一个放弃写入的键仅留下 DIRTY 与 REMOVE。 |
| 中育云笔记，Coil 3 | 3 | 包装器将输入键做 SHA-256，小写十六进制结果用作文件名。第 0 槽是元数据，第 1 槽是数据。原包写出了 24、37 字节两个文件。 |
| 在线专栏，OkHttp | 201105 | HTTP 缓存的第 0 槽用于响应元数据，第 1 槽用于正文。本次直接用原包磁盘缓存类写入 24、37 字节的本地测试值，核对两个槽的内容和长度。 |

### 云笔记的 page_mdb

NewPaintFragment 复制笔记时调用原包 ObjectBox 构建器打开 page_mdb，并在事务中更新 PageEntity。NotePageOrder 会把 data.mdb 和 lock.mdb 识别为两个不同的文件。用云笔记 APK 的模型、实体游标及原版 ARM JNI 库，在模拟器中创建了 24 种实体各一行，关闭并重新打开后，原包成功读取全部 24 行。样本中的页名、文字和命令字节均在本地生成。[原生写入与回读](evidence/art/cloud-store-android.txt) · [原文件](evidence/board/page_mdb/data.mdb)

该 81,920 字节的样本能由 LMDB 读取。主 B 树既包含表和属性元数据，又包含按实体编号和对象 ID 编址的行。表和行值均能按 FlatBuffers 读取。行的八字节键为大端，当前样本的高六位为 6，随后 24 位为实体 ID，低 34 位为对象 ID。每个业务字段用属性 ID 减一作为 FlatBuffers 槽号。读出的 24 个实体和 140 个属性的名称、类型、ID、UID 与 APK 内模型全部一致。主机解码器还逐字段核对了页面与标题的关联、文本的字号和颜色、布尔状态，以及命令和音频实体中的字节数组。lock.mdb 包含 LMDB 锁状态，离线解码使用已关闭数据库的 data.mdb 副本。[解码结果](evidence/board/page_mdb/decoded.json) · [字段核对](evidence/art/cloud-store-host.txt)

读取本地文件需要系统提供 mdb_dump。仅查看某张表时，可使用 `python3 tools/read-data.py 路径/data.mdb --entity PageEntity`。本工具读取实体、属性和行，关系字段输出目标对象 ID。

新版云笔记 BoardControl.loadDirAsMdbFmt 根据 page_mdb 目录是否存在选择路径。有数据库时，以笔记目录路径查询 BlackBoardEntity。没有数据库、同时有 page_router.bin 时，则运行原生 BIN 转 MDB 导入器。后者要求每页有完整 Header。Flutter 的「按页面 BIN 导出云笔记副本」会为选中的笔记补齐每页头，并从副本中省去该笔记的 page_mdb。该副本以 BIN 中的内容为准，数据库独有的内容可放在「导出 ZIP」得到的完整备份里。对仅有字段 1 的页头，副本按 PageHeader 解释为时长；缺页头时继承根头，多页情况下清除无法可靠分摊的总时长。

在 Chromium 打开同时含数据库和 BIN 的[本地测试包](evidence/board/cloud-mixed.zip)，给页面加一笔并选择云笔记副本。云笔记原 APK 的导入事务把该副本写为 38 行。新库有一页、一个手写命令、16 个坐标点、一个文字图元、两个几何图元和一条图片引用。主机独立读回 800 × 600 的页面、875 毫秒时长、中文文字和 PNG 名称。此测试覆盖源代码中的本地导入分支，教学账号的笔记同步仍缺实测。[网页导出包](evidence/board/web-cloud-note.zip) · [原生导入](evidence/art/cloud-store-android.txt) · [导入后的数据库](evidence/board/page_mdb/web-import.mdb) · [逐字段结果](evidence/board/page_mdb/web-import.json)

业务实体及请求、响应模型的字段另见逐应用 storage-models.json。每条记录包含字节码位置、字段类型、可恢复的泛型签名和显式 Gson 键名。仅有 Java 字段时，实际序列化还取决于调用方与适配器。SharedPreferences 可按 Android XML 中的 string、boolean、int、long、float 和 set 解析；AndroidX Preferences DataStore 的 PreferenceMap 用字符串作键，值为 bool、float、int32、int64、string、字符串集合、double 或 bytes 的 oneof。read-data.py 支持 .preferences_pb，也能按优课畅学 APK 自带定义解码 login-server、user-profile 与 ota-settings。Java 对象流和媒体调用位置见 storage.json。[新测评模型字段](https://github.com/Loshop-Studio/zhongyu-android-reverse/blob/main/reports/apps/%E6%96%B0%E6%B5%8B%E8%AF%84/storage-models.json)

### ObjectBox 独立保存的一对多关系

一笔手写的页面归属可以沿 PageEntity、RecordEntity、TouchRecordEntity、TouchEventEntity、TouchInfoEntity 追踪。前几步使用保存的单值 ID；后两步使用独立的 ToMany 关系。原始导入生成的触摸点行可以有值为零的 recordId，同时仍属于笔迹。双页样本可由存储的关联独立追溯到页面。[双页样本的归属核对](evidence/board/new-notebook-cloud.json)

在交换给网页的这些数据库中，实体目录同时列出关系 ID、UID、源实体 ID 与目标实体 ID。实测的 12 字节关系键由三个大端 uint32 组成，后两项是对象 ID。正向的首项为 0x08000000 加关系 ID 左移两位；反向首项另加 2，后两项互换，值均为空。解码器配对两个方向，并报告未识别的关系键数量。通过原 APK 创建独立的合成库，每种关系均写入三条关联，含共享目标。原包关闭、重开后逐个读取了十一种关系的 33 条关联；主机从 66 个正反向索引键恢复同样的集合，十一组关系 ID、UID 与源、目标实体也和应用模型一致。[原包回读](evidence/art/store-relations-android.txt) · [全部关系明细](evidence/board/page_mdb/relations.json) · [可独立解码的样本](evidence/board/page_mdb/relations.mdb)
